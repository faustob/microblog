- ⚠ qr-metric-naming (`app/telemetry.py`): The two sibling duration histograms record different units under identically shaped names: `web.vital.lcp.duration` is recorded in seconds (value/1000.0 in routes.py) while `web.vital.inp.duration` is recorded in milliseconds, and neither name discloses its unit. Consumers of `web.vital.*.duration` cannot tell which scale a series uses. — _Pick one unit for all web-vital duration histograms (seconds is the semconv style) and convert every value at the record site, e.g. record INP as value/1000.0 with unit='s'; or make the unit explicit in the name (web.vital.lcp.duration with unit 's' and web.vital.inp.duration with unit 's')._
- ⚠ general (`app/main/routes.py`): The `http.route` attribute on both web-vital instruments is taken verbatim from the unauthenticated JSON body (`data.get('route')`, only truncated to 128 chars), so any client can push arbitrary strings into a metric dimension and cause unbounded time-series cardinality. — _Validate the reported route against the app's registered rule set (e.g. `{r.rule for r in current_app.url_map.iter_rules()}`) and fall back to 'other' for anything not in that set before using it as an attribute._
- ⚠ general (`app/templates/base.html`): `const vitalsRoute = '{{ request.url_rule.rule ... }}'` is emitted through Jinja autoescaping inside a `<script>` block, and HTML entities are not decoded in script content, so parameterized routes are reported as `/user/&lt;username&gt;` instead of `/user/<username>`, corrupting the `http.route` attribute on the LCP/INP metrics. — _Serialize the value safely for JS, e.g. `const vitalsRoute = {{ (request.url_rule.rule if request.url_rule else 'unknown')|tojson }};`._
- ⚠ general (`app/telemetry.py`): LCP is recorded in seconds into a histogram with no explicit bucket boundaries, so it uses the SDK default boundaries (0, 5, 10, 25, …); virtually every LCP sample lands in the single [0,5) bucket, making the p75 < 2.5s SLI target impossible to evaluate accurately. — _Register a View (or pass explicit_bucket_boundaries_advisory) on the MeterProvider for the web-vital histograms with web-vitals-appropriate boundaries, e.g. [0.1, 0.25, 0.5, 1, 1.5, 2, 2.5, 3, 4, 5, 7.5, 10] seconds for LCP and a comparable ms/s set for INP._
